# Modern Qt / QML guidelines for the GUI base

The best-practice reference and **style guide** for `gui-components` and
everything `edi` builds on it — written to be followed by less-advanced
implementing agents and to be **enforced** (qmllint + CI grep), not just
read. It blends the _classical_ Qt/QML idioms this codebase already uses
well with the _modern_ Qt 6 practices it should adopt. Backed by
[I-0030](../issues/open/I-0030-no-qml-style-guide.md); each rule notes
the audit issue it prevents.

> **How to read this:** rules marked **[MUST]** are enforceable gates;
> **[SHOULD]** are strong defaults; **[KEEP]** are good existing
> practices to preserve. The "classical → modern" callouts show the
> direction of travel.

## 0. First principles

1. The library is **generic**. No product names, no named app pages, no
   network hosts in `Gui/*`. **[MUST]** (I-0006/I-0007). App specifics
   enter only via injected seams (`ApplicationInfo`, a page model,
   optional services — see
   [architecture-target.md](architecture-target.md)).
2. Write app code **once** for desktop and WASM. Anything
   platform-divergent goes behind a façade with a target-aware backend.
   **[MUST]** (I-0002/I-0003).
3. Preserve the design system. Style tokens, Elements→Components
   layering, animated theming are good — extend them, don't replace
   them. **[KEEP]**

## 1. Modules, build & type registration

- **[MUST]** Module URI == import path == directory. `Gui/Style` →
  `module EasyApplication.Gui.Style` →
  `import EasyApplication.Gui.Style`. (I-0009)
- **[SHOULD]** Build QML modules with **CMake `qt_add_qml_module`**
  (generates `qmldir` + resources, compiles QML with `qmlsc`, registers
  types). _Classical → modern:_ hand-written `qmldir` + `.qrc` →
  generated by the module. (I-0004/I-0001)
- **[SHOULD]** Register C++/Python types with
  **`QML_ELEMENT`/`QML_SINGLETON`** (declarative) rather than imperative
  `qmlRegisterType`/`qmlRegisterSingletonType` where the toolchain
  allows. For PySide, prefer the `@QmlElement`/`@QmlSingleton`
  decorators.
- **[MUST]** One public type per file; file name == type name.

## 2. Imports

- **[MUST]** Use **unversioned** imports in Qt 6 (`import QtQuick`, not
  `import QtQuick 2.15`). No mixing styles. (findings-build-qml §QML
  quality)
- **[MUST]** Do **not** import `QtQuick.Controls.impl` (private Qt
  internals) outside a single allowlisted wrapper element. Prefer public
  API or a project-owned element. _Classical → modern:_ private
  `IconLabel`/`PlaceholderText` → project `EaIconLabel` / plain `Text`.
  (I-0011)
- **[KEEP]** `QtQuick.Templates as T` for building custom controls is
  correct and encouraged.
- **[MUST]** Do not import `QtTest` (or other test/tooling modules) into
  shipped UI. (I-0012)

## 3. Properties & data flow

- **[SHOULD]** Prefer **typed** properties over `property var`; type
  enables `qmllint`/`qmlsc` checks. Reserve `var` for genuinely dynamic
  data.
- **[SHOULD]** Use **`required property`** for inputs a component must
  be given, and `setInitialProperties()` from the host — _not_ global
  context properties. _Classical → modern:_ the
  `typeof pyX !== "undefined"` context-property pattern in `Vars.qml` →
  `required property` / injected singletons. This is also what lets
  `qmlsc` compile the file.
- **[MUST]** Expose C++/Python state to QML via `Q_PROPERTY`/`@Property`
  with `NOTIFY` signals and bind to it; never poll. **[KEEP]** the
  existing `Property`/`Signal`/`Slot` backend pattern (`Maintenance.py`,
  `Logging.py`) — it is idiomatic.
- **[SHOULD]** Keep singletons **stateless-ish**: `Style.*` tokens are
  pure; avoid I/O and per-change `console.debug` in singletons. (I-0021)

## 4. Styling, theming, sizing

- **[MUST]** All colours/sizes/fonts come from the `Style` singletons —
  never hard-coded literals in Elements/Components. **[KEEP]** the token
  system.
- **[KEEP]** Animated theme/translation transitions
  (`Behavior on color { EaAnimations.ThemeChange {} }`) — but keep them
  cheap and target-aware.
- **[MUST]** Rely on Qt 6 **automatic HiDPI**; express sizes in logical
  pixels. Do not manually multiply by a device scale (double-scaling
  risk). If a _user_ zoom is wanted, name it `uiScale` and document it.
  (I-0024)
- **[SHOULD]** Read font metrics via `FontMetrics`/`TextMetrics`, not a
  throwaway `Text{}`. (I-0024)
- **[SHOULD]** Prefer **`Layouts`**
  (`RowLayout`/`ColumnLayout`/`GridLayout`) for resizable structure and
  **anchors** for fill/center; avoid absolute `x/y` except for overlays.
  Bind sizes to `Style` tokens, not magic numbers.

## 5. Effects & graphics

- **[SHOULD]** Use **`MultiEffect`** (Qt 6.5+) for blur/shadow/glow
  instead of Qt5Compat `QtGraphicalEffects`. _Classical → modern:_
  `Qt5Compat.GraphicalEffects` (`DropShadow`, `RectangularGlow`) →
  `MultiEffect`. Fewer deps, better performance, WASM-friendly.
- **[SHOULD]** Prefer `layer.enabled` + a single effect over stacking
  many render layers.

## 6. Charts & heavy data views

- **[MUST]** No `QtWebEngine`/`WebEngineView` in shipped code
  (unavailable on WASM). Use the native charting façade. (I-0002)
- **[MUST]** Update series **in place**; never full-reload a view on
  resize, and never push large arrays via `JSON.stringify` over a JS
  bridge. Bind to a model/typed arrays. (I-0016)
- **[SHOULD]** For very large patterns, measure; consider a custom
  `QQuickItem`/`ShaderEffect` only if the native chart misses the frame
  budget.
- **[SHOULD]** Use `Loader`/`asynchronous: true` for heavy off-screen
  pages; reuse delegates in views; avoid instantiating everything
  eagerly (cf. eager `FontLoader`s, I-0015).

## 7. Internationalisation & accessibility

- **[MUST]** Wrap **all** user-visible text in `qsTr()`; use `%1` arg
  substitution, not string concatenation. (I-0017)
- **[SHOULD]** Set `Accessible.role`/`Accessible.name` on interactive
  Elements so screen readers and UI tests can find them (also helps the
  RemoteController-style automation without `QtTest`).
- **[SHOULD]** One canonical translator, wired in `main`, retranslate on
  language change. (I-0029)

## 8. WASM-specific rules

- **[MUST]** Detect the target with `Qt.platform.pluginName === "wasm"`
  and route platform-divergent behaviour through a façade (settings,
  file dialogs, update-check, audio).
- **[MUST]** No file `location:` on `Settings` under WASM (use the
  `localStorage`-backed default). (I-0003)
- **[MUST]** No `QProcess`, no blocking `urllib`/network on the UI
  thread, no `QtWebEngine`, no `QtTest`/`QtMultimedia` on the WASM path.
  (I-0007/I-0012)
- **[SHOULD]** Keep startup light: lazy-load fonts/large assets; prefer
  compiled QML; minimise the embedded resource set (prune unused fonts —
  I-0015).

## 9. Testing

- **[MUST]** Every new component instantiates cleanly under the
  **smoke-load** test (headless, desktop + WASM). (I-0010)
- **[SHOULD]** Interactive Elements get a **Qt Quick Test** (`TestCase`)
  covering their key behaviour; backend logic gets Python unit tests.
- **[SHOULD]** Add each new component to the **gallery** example (visual
  smoke + living doc, I-0025).

## 10. Naming & layering conventions

- **[MUST]** Import aliases: `EaStyle`, `EaElements`, `EaComponents`,
  `EaGlobals`, `EaAnimations`, `EaCharts`, `EaLogic`. **[KEEP]** this
  existing convention.
- **[MUST]** **Elements** = primitives (no app knowledge, `T.*`-based).
  **Components** = composed furniture. Apps use
  `Components.ApplicationWindow`; the primitive base is
  `ApplicationWindowBase` (renamed, I-0028).
- **[SHOULD]** `id: control`/`id: root` for the top item; lowerCamelCase
  ids; PascalCase types; signals `verbNoun`, handlers `onVerbNoun`.
- **[MUST]** No `console.log`/`print` debugging left in committed code;
  route intentional diagnostics through the logger behind a flag.
  (I-0021)

## 11. Python ↔ QML boundary (PySide path)

- **[KEEP]** `QObject` backends exposing `@Property(notify=…)`, `@Slot`,
  `Signal` — bind QML to these.
- **[SHOULD]** Inject objects with
  `engine.setInitialProperties`/registered singletons over
  `rootContext().setContextProperty` (context properties defeat
  `qmllint`/`qmlsc`). _Classical → modern._
- **[MUST]** No import-time side effects (file I/O) in backend modules.
  (I-0022)
- **[MUST]** Guard external parsing/network (no unguarded `matches[0]`;
  single fetch per action). (I-0008)

## Enforcement summary (wire these gates)

| Rule                                                                   | Gate                      |
| ---------------------------------------------------------------------- | ------------------------- |
| Unversioned imports, no private `.impl`, module identity               | `qmllint` (G04)           |
| Formatting                                                             | `qmlformat --check` (G04) |
| No `easydiffraction` / named pages in `Gui/*`                          | CI grep (G03)             |
| No `Settings{location}` in screens; no `QtWebEngine`/`QtTest` in `src` | CI grep (G02/G03)         |
| No dangling manifest paths; no spaces in `src/` filenames              | CI script (G01-T4)        |
| Every component smoke-loads                                            | Qt Quick Test (G04-T2)    |
| `qsTr()` on user text                                                  | lint heuristic (G07)      |

When a rule here is checkable, prefer a gate over a review comment —
reviews don't scale to less-advanced agents; gates do.
