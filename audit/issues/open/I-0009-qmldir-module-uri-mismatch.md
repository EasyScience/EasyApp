# I-0009: `qmldir` module names don't match the import URIs

- **Status:** open
- **Priority:** High
- **Area:** build
- **Targets:** both
- **Found:** 2026-07 GUI base audit
- **Related:** I-0004 (CMake fixes this by construction), I-0011;
  milestone G01

## Problem

Every `qmldir` declares a **bare** module name, but every consumer
imports a **dotted** URI:

| `qmldir` says                                                             | QML imports                           |
| ------------------------------------------------------------------------- | ------------------------------------- |
| `module Style` (`Gui/Style/qmldir`)                                       | `import EasyApplication.Gui.Style`    |
| `module Elements`                                                         | `import EasyApplication.Gui.Elements` |
| `module Globals`                                                          | `import EasyApplication.Gui.Globals`  |
| `module Components`, `module Charts`, `module Logic`, `module Animations` | `import EasyApplication.Gui.<X>`      |

It "works" only because Qt's directory-based resolution finds
`EasyApplication/Gui/Style/qmldir` under the import path and then
largely ignores the mismatched `module` line. But:

- `qmllint`, `qmlcachegen`/`qmlsc`, and Qt Design Studio expect
  `module <URI>` to equal the import URI; the mismatch produces warnings
  and defeats static analysis.
- `qt_add_qml_module` (I-0004) **requires** `URI == import path`; you
  cannot migrate cleanly until the module identity is consistent.
- Two modules also omit version tags entirely (`Gui/Charts/qmldir`,
  `Gui/Animations/qmldir` list `Type Type.qml` with no `1.0`),
  inconsistent with the versioned `Elements`/`Style` modules.

## Impact

- Static QML tooling (lint, compiled QML, Designer) is effectively
  unusable, which is part of why QML quality problems (I-0010, I-0011)
  go uncaught.
- Blocks the CMake/`qt_add_qml_module` migration that removes the I-0001
  class of bugs.

## Suggested fix

**Recommended:** fold this into I-0004 — when you declare each module
with `qt_add_qml_module URI EasyApplication.Gui.Style …`, the generated
`qmldir` gets the correct URI automatically and this issue disappears.

**If fixing the hand-written `qmldir` first (stop-gap):**

1. Set each `module` line to the full URI, e.g. `Gui/Style/qmldir` →
   `module EasyApplication.Gui.Style`; repeat for `Elements`, `Globals`,
   `Components`, `Charts`, `Logic`, `Animations`, and
   `Logic/Maintenance`.
2. Add consistent version tags (`1.0`) to the `Charts` and `Animations`
   entries.
3. Re-run `qmllint` against each module and confirm the module-identity
   warnings are gone.

## Acceptance criteria

- For every module, `qmllint` reports no "module identifier does not
  match" warning.
- Either the `qmldir` files carry the full-URI `module` line, or they
  are generated by `qt_add_qml_module` with the correct URI (preferred).
